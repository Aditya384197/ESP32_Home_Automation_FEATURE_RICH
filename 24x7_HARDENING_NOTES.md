# 24/7 hardening revision — file map

## ESP32 files changed

### `main/main.c`
Replace the existing file with this version.

Main hardening:
- bounded STA reconnect backoff in a dedicated task
- safer cJSON request parsing
- safer JSON response generation for configurable strings
- relay persistence only after actual state changes
- three-attempt retry for relay-state NVS writes
- scheduler task watchdog coverage
- existing local-first/captive-portal behavior preserved
- OTA intentionally untouched

### `main/cloud_client.c`
Replace the existing file with this version.

Main hardening:
- 5-second normal cloud polling
- exponential failure backoff up to 60 seconds
- HTTPS-only cloud endpoint
- safer URL joining
- no large per-request heap response allocation
- truncated response detection
- command IDs + explicit acknowledgement queue
- 5-minute command expiry is enforced by the backend
- schedule cache is written to NVS only when the schedule actually changes
- schedule cache migration retained

No API-breaking change is required; the existing file remains compatible.

## Deployment order

### New installation
1. Build the project.
2. Flash the bootloader, partition table, and application generated by the build.
3. Configure the local AP and optional STA/cloud settings.

### Existing ESP32 installation
1. Back up the current NVS/configuration if the device contains important settings.
2. Build this source revision using the same ESP-IDF target/version.
3. Flash the normal factory application using the unchanged `partitions.csv`.
4. Verify local AP control first.
5. Verify physical switches and relay persistence.
6. If cloud is used, deploy the Worker schema/migration changes before testing remote commands.

OTA is deliberately not used for this replacement.
